## What this project does

**CityCheck** is an IFC validator and georeferencer for Montevideo. Users upload an IFC (BIM) file, optionally associate it with a cadastral parcel ID (*padrón*), and see it rendered in two side-by-side viewers: a standalone 3D IFC viewer and a Mapbox 3D map. The backend API can georeference the IFC and return a modified file for download.

## Architecture

### Routing

TanStack Router with file-based routing. **Never edit `src/routeTree.gen.ts` manually** — it is auto-generated by the `TanStackRouterVite` Vite plugin when routes change.

Routes:
- `/` — landing page (`src/routes/index.tsx` + `src/components/dashboard/`)
- `/validator` — main feature (`src/routes/validator.tsx`)

### Data fetching

TanStack Query (`@tanstack/react-query`) via hooks in `src/hooks/`. All HTTP calls go through the typed helpers in `src/api/index.ts` (`apiJson`, `apiJsonOrNull`, `apiBlob`). The API base URL is prepended automatically by `apiUrl()`.

Backend endpoints used:
- `POST /api/v1/ifc/site-coordinates` — extract lat/lon from IFC
- `POST /api/v1/ifc/georeference/:parcelId` — returns a georeferenced IFC blob
- `POST /api/v1/ifc/parcel-from-site` — find cadastral parcel from IFC coordinates
- `GET /api/v1/parcels/montevideo/:parcelId` — parcel geometry + centroid

### IFC viewer (standalone)

`src/lib/ifc-viewer.ts` exports `setupIFCViewer(container) → IFCViewerAPI` with `loadIfcFromFile(file)`, `clearScene()`, and `cleanup()`.

Internally uses `createThatOpenIFCRuntime()` from `src/lib/thatopen-ifc-runtime.ts`, which sets up the full `@thatopen/components` stack (Components, Worlds, SimpleScene, OrthoPerspectiveCamera, SimpleRenderer, IfcLoader, FragmentsManager). The WASM IFC parser (`web-ifc`) is served from `/web-ifc/` (copied there by `vite-plugin-static-copy` at build time).

### Map viewer (Mapbox + Three.js)

Three-layer class hierarchy in `src/components/map-box/`:

1. **`BimModel`** (`index.ts`) — React-facing orchestrator. Lives in a `useRef` in `MapViewer`. Creates `MapBox` lazily on first `setFile()`, exposes `dispose()`, `clearScene()`, `applyParcelClip()`.
2. **`MapBox`** (`map-box.ts`) — Mapbox GL map + Three.js custom layer. Owns the WebGL renderer (shared canvas with Mapbox), the Three.js scene, and the Mercator model transform. On each frame, multiplies Mapbox's projection matrix by the model's Mercator transform and renders the Three.js scene.
3. **`FragmentModel`** (`fragments.ts`) — loads IFC into the Three.js scene using the same `@thatopen/components` stack via `createThatOpenIFCLoader` (thin wrapper around `thatopen-ifc-runtime`). The `onLoadFinish` callback lets `MapBox` re-center the map after loading.

The map centers on (in priority order): explicit parcel centroid from the API → `IfcSite` `RefLatitude`/`RefLongitude` from IFC properties → default Montevideo center.

The Mapbox `clip` layer (`parcel-clip-source`) uses the parcel's polygon to hide base-map symbols and models without affecting the IFC custom layer.

#### IFC projection on the map, coverage, and bounding box

The custom layer multiplies Mapbox's projection matrix each frame by `mapCamera`: translation to a `MercatorCoordinate` at the map center, scale from `meterInMercatorCoordinateUnits()` times `modelScaleMultiplier` (with a negated Y component, Mapbox custom-layer convention), and `_modelRotate` (default `rotateX = π/2`) so IFC sits on the map ground plane.

**Glossary (plain language):** *Footprint* = ground area (plan view) of the building in IFC length units² (usually m²). *Axis-aligned bounding box* (**AABB**) = smallest 3D box with faces parallel to X/Y/Z that contains the whole model; `getWorldBbox` returns its min/max on each axis. *InstancedMesh* = one base geometry drawn many times with per-instance transforms (ThatOpen uses this); iterating only base `position` vertices misses copies.

**Comparable areas:** `getParcelAreaMercator()` projects the parcel ring to Mercator and uses the shoelace formula. Dividing by `s²` (`s` = same meters→Mercator factor as the model) yields parcel area in **IFC length units squared**, matching the model footprint used in `estimateCurrentCoveragePercent` / `autoScaleToTargetCoveragePercent`.

**ThatOpen / `InstancedMesh` fix — why it broke before:** (1) Fragments use instancing: many copies, one base geometry. (2) Old code measured size by transforming only base `position` with `mesh.matrixWorld`, **not** each instance’s `instanceMatrix`. (3) The axis-aligned bounding box then wrapped only a tiny portion of the real building → **ground footprint ≈ 0**. (4) `autoScaleToTargetCoveragePercent` divides by that footprint → **multiplier explodes** → model huge on map. The projection stack was fine; the **input measurement** was wrong. **Fix:** `Box3.setFromObject(fragmentRoot)` so Three.js includes every instance in the box.

**Footprint axes:** In fragment space, **Y is up** before the map's `rotateX`. Horizontal footprint is **`(xMax - xMin) × (zMax - zMin)`**, not X×Y (that would mix building height into the ground extent).

### `@thatopen/fragments` and Vite

`@thatopen/fragments` and `@thatopen/components` are excluded from Vite's `optimizeDeps` because they use Web Workers internally. The worker URL is resolved at runtime via:

```ts
const workerUrl = new URL('@thatopen/fragments/worker', import.meta.url).href;
```

## Key gotchas

- **`routeTree.gen.ts` is auto-generated.** Adding or renaming a file in `src/routes/` regenerates it on the next dev server start or build.
- **`web-ifc` WASM path.** `IfcLoader` is configured with `autoSetWasm: false` and `path: '/web-ifc/'`. In dev, Vite serves the `.wasm` files from `node_modules`; in production, they are copied to `dist/web-ifc/` by `vite-plugin-static-copy`.
- **`bim-fragment` three.js override.** `package.json` has an `overrides` block forcing `bim-fragment` to use the same `three` version as the rest of the project to avoid duplicate Three.js instances.
- **MapBox renderer shares the Mapbox canvas.** `WebGLRenderer` is created with `canvas: map.getCanvas(), context: gl` so both Mapbox and Three.js render to the same WebGL context. `renderer.autoClear = false` and `renderer.resetState()` before each Three.js render are essential for this to work.
- **`BimModel` is re-created on parcel/file change.** `MapViewer` computes a `bimSessionKey` from the parcel ID and file identity; when it changes the entire `BimModel` (and its Mapbox map) is destroyed and recreated. This avoids stale WebGL/Three state.
- **IFC bounding box on the map:** use `Box3.setFromObject` (not hand-rolled vertex loops) so **instanced** fragment geometry is fully enclosed; use **X×Z** for ground footprint, not X×Y — see *IFC projection on the map, coverage, and bounding box* above.
